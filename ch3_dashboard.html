第 3 章

EMQX Dashboard 導覽

EMQX Dashboard 導覽：側欄各模組、Overview 與監控概覽、授權 banner、語言與版本資訊，以及從 Home Assistant 開啟 Web UI 的方式。

為什麼要學這個

EMQX 把 broker 的大小事都收進 Dashboard 這張管理介面。如果你只想靠設定檔案與 Log 逐一猜狀態，一定會掛掉一大半除錯循環——誰連上了、哪個訂閱有沒有成立、訊息是否有送出去，這些 Dashboard 用幾張卡片就講清楚。

這章目標是讓你把「這張介面的地圖」先在腦海裡建起來：側欄各模組管什麼、Overview 頁重點指標放在哪裡、版本與授權去哪確認。之後每一章（驗證、ACL、Listeners、Connector、監控、備份）你都會知道該前往哪個選單，而不是第一次操作才開始找。

核心概念

EMQX Dashboard 是內建的管理主控台，預設以 HTTP 監聽連接埠 18083。在 Home Assistant 裡，你可以用 Ingress（左側欄 EMQX 圖示）直接開，也可以開 http://<主機>:18083。

有個概念值得先記：Dashboard 只是可視化操作層，你不用開啟它 EMQX 也照常收發訊息。它的作用是讓你在一個地方監控叢集、連線、訂閱、規則與安全設定，而不是 broker 的必要零件。

登入後進首頁「Cluster Overview」（叢集總覽），這是整個 Dashboard 的地基。它告訴你「目前有多少連線與訂閱、訊息進出速率、叢集裡有幾個節點」，是你在任何排錯之前最該先瞄一眼的地方。

動手做

  1. 從 Home Assistant 開

    Home Assistant 左側找 EMQX 圖示（Ingress 入口），點下就會開 Dashboard。

  2. 或直接打 18083

    瀏覽器開 http://<主機位址>:18083。兩種進法都是同一座 Dashboard。

  3. 登入並先改密碼

    以 admin／public 首次登入，依系統指示改成自己的密碼（見第 2 章）。

  4. 把側欄走一遍

    沿左欄從 Monitoring、Access Control、Integration，一路看過 System，把每個模組的「用途一句話」記下來。回到 Monitoring → Cluster Overview 再看一次整体。

Overview 總覽在看什麼

Dashboard 首頁是 Cluster Overview，上半部左右兩張卡是核心指標：

  • Message Rate（訊息速率）：系統每秒進出的訊息量，左上角卡片即時呈現。
  • Connections／Subscriptions／Topics：目前連線數、訂閱總數、唯一主題數；連線一有變化就即時更新。

下方是時間序列圖表，可選「過去 1 小時、6 小時、12 小時、1 天、3 天、7 天」來觀察連線數與訊息量走勢。圖太多訊息時，可以用「Reset Monitoring Data」把前面資料清掉，重新累積。

切到 Nodes 分頁，你能看整個叢集每個節點：名稱、狀態、持續運行時間、連線數、版本、Erlang 處理程序數、記憶體與 CPU 用量。節點畫成灰色表示它已停止。點節點名稱可再進「節點細節」看 system paths、log 路徑與更細統計。

要找目前運作的 EMQX 版本（本書目標是 5.8.9），最直接的地方就是 Nodes 分頁的版本欄。

側欄模組與語言／授權

Dashboard 左側選單大致分成下面幾組：

側欄群組你的主用途
Monitoring看叢集總覽、連線、訂閱、retained 訊息
Access ControlAuthentication 與 Authorization（驗證與授權）
IntegrationRule Engine 與資料整合（Connectors、Actions、Sources、Sinks）
ManagementCluster Settings、Advanced MQTT、Extensions
DiagnoseWebSocket 測試、slow subscriptions、topic metrics
System使用者、API key、audit log、License、單一登入

要看 License（授權），進 System 相關頁面確認授權狀態與效期；要看 版本，用 Nodes 分頁的版本欄。Dashboard 的語言通常在右上角使用者選單或偏好設定切換，把它改成你舒服的語言即可。

一個實用的歸納法：驗證與權限在 Access Control；把資料搬出去、寫規則，在 Integration；日常檢查先在 Monitoring。記住這三個落點，後續章節的選單路徑你就不容易迷路。

故障排除

  • 登入後 Dashboard 進不去：確認走的是 Ingress 還是 18083；若主機在其他網段，改打 http://<主機位址>:18083。
  • 找不到「版本」：進 Monitoring → Nodes，節點名稱旁的 version 欄就是目前運行的版本（預期 5.8.9）。
  • 某個側欄沒有出現：進階功能（例如 Delayed Publish、Alarms）在 Open Source 版預設不顯示，是正常的，不代表壞掉。
  • 首頁數字似乎沒更新：Overview 的圖有時間範圍可選；要重新累積可用「Reset Monitoring Data」。

常見問題

Dashboard 一定要啟動嗎

不必。EMQX 即使不開 Dashboard 也照常收發 MQTT 訊息，Dashboard 只是管理介面。是以圖方式操作、監看與除錯的便利層。

語言在哪切換

通常在右上角使用者選單或偏好設定裡。換語言不會影響 broker 的行為，純粹是操作方便。

Overview 裡的「節點」是什麼

每個 EMQX 實例就是一節點。你家用 add-on 通常一個節點；叢集才是多節點。Nodes 分頁能看每個節點的狀態、版本與系統資源。

為什麼有些功能在側欄看不到

進階資料整合與安全功能多屬 EMQX Enterprise（付費版）。Open Source 5.8.9 不顯示這些項目，不是設定出錯。
